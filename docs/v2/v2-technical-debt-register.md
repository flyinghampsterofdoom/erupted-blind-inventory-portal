## Maintenance rules

1. Add an entry when work is deliberately deferred, not merely discovered.
2. Reference the debt ID from module or release documents when it affects rollout.
3. Close an entry only with implementation and verification evidence; retain its history in version control.
4. A P0 item blocks the release scope it names. A conditional P0 blocks only when that module is included.
5. Do not use this register to imply approval for a new feature, destructive migration, V1 cutover, or V1 retirement.
