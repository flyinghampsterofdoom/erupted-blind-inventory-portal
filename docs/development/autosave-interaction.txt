Autosave interaction correction — October 25, 2026

Scope
Change Box Count, Daily Chore Sheet and Non-sellable Stock Take share
app/static/v2/inventory-form-drafts.js. Ordinary draft saves formerly included
busy in the editable-control lock, discarding keyboard focus and keystrokes.
The early busy return also silently discarded Submit during an autosave.

Correction
Background saves now share one running promise without disabling controls.
Each pending command retains its field snapshot, generation, operation ID and
expected revision. Its acknowledgment advances only that generation; newer
edits remain protected locally and drain afterward. Background follow-ups
coalesce behind the remaining 800 ms debounce; explicit Save and Submit drain
immediately. This prevents fast acknowledgments from causing per-keystroke POSTs. Responses never refill
editable controls. Older chore acknowledgments do not repaint completion times
over newer checkbox edits. The input debounce remains 800 ms.

Submit synchronously queues intent and locks the final entry set. The same
runner saves every required generation before issuing the final command.
Repeated clicks share that runner. Failed required saves cancel queued Submit
with an actionable message; retrying a draft does not silently submit later.
An unconfirmed final command remains protected and locked, and Retry checks
the authoritative receipt before repeating it. The final command is retained
until its own receipt is verified rather than cleared before verification.

Network waits have a 20-second application deadline, including response-body
parsing. POSTs and state reads get AbortSignals. Shared session/key reads are
bounded for this caller without changing their shared implementation; an
underlying shared read may finish later. Timeout is an unknown outcome, not
proof of rollback. Exact operation IDs/payloads are retained for safe retry.
Browser storage encryption and ordered local persistence are unchanged.

Bootstrap, identity/store changes, conflicts, storage failures and final
submission continue to fail closed. Server validation, authorization, row locks,
revision checks, receipt lookup and live-inventory behavior are unchanged.
Explicit logout also freezes its last snapshot through final local protection,
preserving the previous logout safeguard while ordinary saves remain editable.
No schema, key format, backend query, scheduler or CI/CD change is included.

Recovery and rollback
Encrypted v2 envelope, permanent identities, key versions, revision tokens and
pending-command schema have not changed. Existing recovery/identity suites
cover retained drafts, rotation, authorization and replay. Queued Submit intent
is in memory until a final command is persisted; refreshing while it waits
restores entries but requires explicitly submitting again. A persisted final
command recovers by its receipt. Unresolved conflicting drafts remain retained
for review; they are not silently imported or erased.

There is no database rollback. A future authorized rollback can restore the
previous application asset through the approved release procedure, retaining
the current keyring, database, identities and protected browser work. An old
controller restores the former input-freeze behavior; do not clear browser
storage to force a rollback. Open tabs retain their already-loaded JavaScript:
finish/reconcile pending submissions before asking an employee to reload.
Do not force a refresh during an unconfirmed final submission.
